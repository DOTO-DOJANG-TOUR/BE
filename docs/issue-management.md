# Issue 관리 규칙

## 자동화

Issue Form으로 이슈를 생성하면 다음 작업을 자동으로 수행합니다.

- 이슈 작성자를 assignee로 지정합니다.
- 템플릿에 선언된 기능 유형 라벨을 적용합니다.
- `완료 목표` 선택값을 `D-n` 라벨로 적용합니다.
- `중요도` 선택값을 `Critical`, `High`, `Medium`, `Low` 라벨로 적용합니다.
- `labels.json`이 `main` 또는 `develop`에 반영되면 라벨을 생성하거나 최신 정의로 갱신합니다.

GitHub 정책상 이슈 작성자를 assignee로 지정할 수 없는 경우에는 할당만 건너뛰며 라벨 처리는 계속합니다.

## 라벨 역할

| 종류 | 의미 |
|---|---|
| `🐛 Bug`, `✨ Feature`, `📚 Docs`, `♻️ Refactor`, `🛠️ Chores` | 작업 유형 |
| `🔴Critical`, `🟠 High`, `🟡 Medium`, `🟢 Low` | 장애·비즈니스 영향도 |
| `D-0` ~ `D-7` | 완료 목표까지 남은 날짜 |

중요도와 D-day는 별개입니다. 영향도가 높아도 일정상 나중에 처리할 수 있고, 영향도가 낮아도 배포 일정 때문에 빠르게 끝내야 할 수 있습니다.

## D-day 규칙

- 이슈 생성 시 `D-0`, `D-1`, `D-3`, `D-7`, `일정 미정` 중 하나를 선택합니다.
- `D-n`이 붙은 열린 이슈는 매일 KST 00:00에 하루씩 감소합니다.
- `D-0`은 자동 제거하지 않습니다. 완료하거나 일정을 다시 합의할 때 이슈를 닫거나 완료 목표를 수정합니다.
- Issue 본문의 완료 목표를 변경하면 기존 D-day 라벨을 새 선택값으로 교체합니다.
- D-day 라벨을 수동으로 여러 개 붙이지 않습니다.

## 관련 워크플로

- `issue-metadata.yml`: 작성자 할당, 중요도와 최초 D-day 라벨 적용
- `issue-d-day-labeler.yml`: 열린 이슈 D-day 일일 갱신
- `sync-labels.yml`: `labels.json`의 라벨 생성 및 수정
